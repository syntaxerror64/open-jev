Open-source реконструкция с нуля на PyTorch идей
[моделей Jev / System One от TypeSafe
AI](https://typesafe.ai/blog/introducing-system-one-models-and-jev):
на вход — неструктурированное состояние программы, на выход — типизированные
вероятностные решения.

> [!IMPORTANT]
> Это неофициальная исследовательская реализация. Опубликованный чекпоинт
> обучен дистилляцией — исследовательского уровня, без внешних бенчмарков.
> Это не продакшн-модель Jev; данные и веса TypeSafe AI не воспроизводятся,
> совпадение с их опубликованными результатами не заявляется.

## Идея

Jev позиционируется как модель *system one*: на вход поступает
неструктурированное состояние программы, на выход — типизированные
вероятностные решения.

Вместо генерации текста по токену за раз эта реализация кодирует состояние
один раз и отвечает на каждый вопрос через небольшие типизированные
readout-головки.

```text
JSON-подобное состояние ──> бидирекциональный энкодер ──> общий кэш состояния
                                                              │
                          слоты вопросов ── cross-attend ─────┘
                                  │
                    ┌─────────────┼─────────────┐
                    ▼             ▼             ▼
                  noul          choice         score
                 p(true)      p(options)     p(levels)
```

Вопросы изолированы друг от друга и сворачиваются в измерение батча. Они
могут обращаться к общему состоянию, но не к другим вопросам. Результат —
один параллельный forward-проход, выходы которого ограничены объявленными
типами.

## Ключевые особенности

- **Типизированные ответы.** `Noul` возвращает p(true), `Choice` считает
  softmax только по вариантам, объявленным во время выполнения, `Score`
  возвращает распределение по уровням рубрики и его математическое ожидание —
  ответ `Choice` не может оказаться тем, чего вы не предлагали.
- **Одно кодирование — много вопросов.** Бидирекциональный трансформер
  кодирует вложенное состояние один раз в общее представление с кэшированием;
  каждый вопрос пересекается с этим кэшем через обучаемые query-слоты.
  Использование кэша и масштабирование числа вопросов замерены в
  [benchmarks/RESULTS.md](benchmarks/RESULTS.md).
- **Уверенность, о которой можно рассуждать.** Evidential-головка моделирует
  эпистемическую уверенность отдельно от вероятности класса; альтернатива на
  основе разброса (spread) выбирается конфигурацией.
- **Обучение по мягким таргетам.** `RLCDLoss` сочетает soft-target NLL,
  Brier score, consistency, evidential и ECE по полным распределениям — никогда
  не по one-hot меткам — поэтому разногласия и неопределённость остаются
  видимыми.
- **Воспроизводимые артефакты.** Каждый релиз содержит `.pt`-чекпоинт и
  JSON-манифест с `sha256`; конфигурация модели едет внутри артефакта, поэтому
  `JevConfig(**manifest["config"])` восстанавливает точную форму — ни одно
  число не нужно принимать на веру.
- **Проверено конструкцией.** Набор из 150 тестов проверяет структурные
  гарантии (типизированные ответы, нормированные распределения, изоляция
  вопросов, использование кэша) и блокирует каждый `git push`.

Реализация намеренно небольшая и читаемая. Токенизатор по умолчанию —
детерминированный хеш-токенизатор; обучаемый BPE-токенизатор (создаётся
командой `python -m scripts.train_bpe` из текста самого репозитория)
реализует тот же интерфейс и подаётся в `Jev` по желанию.

## Установка

```bash
git clone https://github.com/syntaxerror64/open-jev.git
cd open-jev
python -m pip install "torch>=2.0"
```
Рекомендуется Python 3.10 или новее.

## Быстрый старт

```python
import torch

from open_jev.main import Choice, Jev, JevConfig, Noul, Score

model = Jev(
    JevConfig(
        vocab_size=4096,
        d_model=128,
        n_heads=4,
        d_ff=512,
        n_state_layers=3,
        n_readout_layers=4,
    )
).eval()

state = {
    "customer": {"tier": "enterprise", "tenure_months": 34},
    "message": "This is the third duplicate charge. Please fix it.",
    "policy": "Duplicate charges are refundable within 60 days.",
}

questions = [
    Noul("The customer is requesting a refund.", key="wants_refund"),
    Choice(
        "Which team should handle this?",
        options=["billing", "technical", "account"],
        key="route",
    ),
    Score(
        "How frustrated is the customer?",
        labels=["calm", "annoyed", "frustrated", "very frustrated"],
        key="frustration",
    ),
]

with torch.no_grad():
    answers = model([state], questions)[0]

for answer in answers:
    print(answer)
```

Этот фрагмент создаёт свежую модель со случайной инициализацией и никогда не
загружает чекпоинт, поэтому значения выше не несут смысла; опубликованный
чекпоинт (см. [Опубликованные чекпоинты](#опубликованные-чекпоинты)) обучен
дистилляцией. Полезная гарантия здесь структурная: ответ `Choice` может быть
только одним из предложенных вариантов.

Запустить полное демо, включая один шаг обучения, ориентированного на
калибровку:

```bash
python example.py
```

`forward.py` — минимальный пример: только инференс, без шага обучения.

## Обучение

`RLCDLoss` ожидает распределения вероятностей, а не one-hot метки. Это
позволяет разногласиям и неопределённости оставаться видимыми, вместо того
чтобы толкать каждый пример к уверенности.

```python
from open_jev.main import RLCDLoss

targets = [
    torch.tensor([[0.08, 0.92]]),
    torch.tensor([[0.80, 0.05, 0.15]]),
    torch.tensor([[0.02, 0.10, 0.48, 0.40]]),
]

loss_fn = RLCDLoss()
loss = loss_fn(model, [state], questions, targets)
loss.backward()
```

Для consistency-обучения передавайте семантически эквивалентные состояния через
`augmented_states` — например, перефразировки или переставленные ключи
словаря.

Тренировочный пайплайн оборачивает этот лосс в возобновляемый цикл со слоем
учителя, поставляющим мягкие таргеты (никогда не метки из датасета):

```bash
python -m pipeline.train --config pipeline/examples/tiny.json --steps 30
python -m pipeline.train --config pipeline/examples/tiny.json --steps 10 \
       --resume runs/tiny/checkpoint.pt
```

## Опубликованные чекпоинты

Обученные запуски экспортируются в версионированный формат v1 (`state_dict`,
конфиг, шаг, метрики, `sha256`) и публикуются как ассеты GitHub Releases:

| Релиз | Артефакты | Статус |
|---|---|---|
| [v0.2.0](https://github.com/syntaxerror64/open-jev/releases/tag/v0.2.0) | [`jev-real.pt`](https://github.com/syntaxerror64/open-jev/releases/download/v0.2.0/jev-real.pt) + [`jev-real.json`](https://github.com/syntaxerror64/open-jev/releases/download/v0.2.0/jev-real.json) (6.3 МБ) | Обучен дистилляцией: учитель Qwen2.5-0.5B, 500 строк Alpaca, 200 шагов |
| [v0.1.0](https://github.com/syntaxerror64/open-jev/releases/tag/v0.1.0) | `jev-tiny.pt` + `jev-tiny.json` (2.3 МБ) | Случайная инициализация — заменён |

Проверьте скачанный файл по манифесту или загрузите его прямо из релиза:

```bash
sha256sum jev-real.pt                       # должно совпасть с "sha256" в jev-real.json
JEV_CHECKPOINT_URL=<asset-url> pytest tests/test_checkpoint_release.py -v
```

Чтобы экспортировать и опубликовать запуск самостоятельно:

```bash
python -m scripts.export_checkpoint --run runs/tiny --out dist/jev-tiny.pt
python scripts/release.py --tag v0.1.0 --asset dist/jev-tiny.pt --dry-run
```

`--dry-run` печатает манифест релиза в JSON, не трогая сеть; настоящая команда
запускает `gh release create`, когда обученный артефакт существует.
[MODEL_CARD.md](MODEL_CARD.md) описывает содержимое артефакта и его текущие
ограничения.

## Оценка качества

Сравнение на отложенной выборке: случайная инициализация против
опубликованного чекпоинта v0.2.0 (100 строк, seed 0, `n_bins` 10 — детали в
[eval/COMPARISON.md](eval/COMPARISON.md)):

| Метрика | Random | Чекпоинт (шаг 200) |
|---|---|---|
| ECE | 0.3073 | 0.1532 |
| Brier | 0.3133 | 0.1509 |
| NLL | 0.8850 | 0.6695 |
| Consistency (сим. KL, меньше — лучше) | 0.006497 | 0.0001031 |

**Что измеряют эти числа.** На отложенной выборке нет ground-truth меток:
ECE, Brier и NLL считаются против дистиллированных таргетов учителя, то есть
измеряют *согласованность с учителем на этой выборке* — не правильность и не
внешний бенчмарк. Точная формулировка и происхождение — в
[MODEL_CARD.md](MODEL_CARD.md).

## Разработка

```bash
python -m venv .venv
.venv/bin/pip install "torch>=2.0" --index-url https://download.pytorch.org/whl/cpu
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest
```

Набор тестов лежит в `tests/` и проверяет только структурные гарантии
(типизированные ответы, нормированные распределения, изоляция вопросов,
использование кэша) — свойства, которые выполняются для любых весов, обученных
или случайных. Тесты с маркером `slow` (демо `example.py`) пропускаются
пуш-гейтом ниже; запускайте их обычным `pytest`.

Пуши гейтятся этим набором: включите вложенный хук один раз на клон, и
`git push` не загрузит ничего, пока тесты не пройдут.

```bash
git config core.hooksPath .githooks
```

Для экстренного пуша — `git push --no-verify`.

## Ограничения

- **Типизированный вывод предотвращает нарушения схемы, а не неверные
  ответы.** Калибровку нужно измерять заново под распределительным сдвигом
  перед любым автономным использованием.
- **Небольшая модель, обученная дистилляцией.** 1.57M параметров, 200 шагов,
  500 обучающих инструкций; «обучена» ≠ «хороша» — метрики выше это
  согласованность с учителем, а не правильность. Внешних бенчмарков нет.
- **Исследовательский масштаб.** Независимая реконструкция по публичным
  материалам — данные, веса и опубликованные результаты TypeSafe AI не
  воспроизводятся.
- **Только CPU, только английский.** Разработка и тесты — на CPU-сборках
  `torch` и английских данных; другие языки и ускорители не проверялись.
